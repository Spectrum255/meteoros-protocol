# machine_frame（机器框架）建模说明

- 版本：v1（2026-11-05），Blockbench 5.2.2，`java_block` 格式，工程分辨率 16×16
- 文件：`art/models/machine_frame/machine_frame_v1.bbmodel`（36,556 B）
- 规模：**16 cube / 7 纹理 / 4 组**，16×16×16 单方块，坐标 0..16
- 纹理源文件：`art/models/machine_frame/textures/*.png`（7 张 16×16）
- 渲染：`machine_frame_front.png` / `machine_frame_side.png` / `machine_frame_iso.png`（1066×855，透明底）

## 坐标与朝向约定

- 方块占满 `x,y,z ∈ [0,16]`，底面 `y=0`。
- **正面 = north / -Z**（`z=0` 平面），东 = `+X`，上 = `+Y`。
- 后续接入时如果方块要按 `FACING` 旋转，模型本身固定朝 north，由 blockstate 的 `y` 旋转处理。

## 可复用给后续机器的地方

1. **正面凹槽做法**：4 根框条（z 0..1）+ 一块内凹面板（z 0.86..0.98），比在整面贴纹理更容易做深度；面板开口尺寸直接决定机器的「脸」。
2. **2×2 状态灯**：4 个 0.9×0.9×0.145 的小 cube，背 0.015 嵌进面板；换纹理键即可复用（`status_on` / `status_off`，后续可按相色扩展）。
3. **侧面加强筋**：主体东西内缩 0.12–0.15，筋从方块边界向内伸，视觉上凸出且不越界；3 条间距 4.2 单位（3.0 / 7.2 / 11.4），换机器可直接平移。
4. **平钢 / 瓷白纹理**：`steel.png` 已改成无方向性平钢，可直接用于任何 1 单位宽的筋或边框；`porcelain.png` 的 1px 边光适合做外壳面板。
5. **通风缝**：贴图行做法零 cube；若后续要真凹槽，见下条。

## 已知问题 / 限制

1. **螺栓是贴图不是几何**：受 ≤16 cube 预算限制，四角螺栓画在 `side` 纹理上（1×1 px，标准像素风），近看是 4 个暗点，没有凸起。若要真实几何：+8 cube（每侧 4 颗 0.6×0.6×0.06），会超预算。
2. **通风缝是贴图**：`FrontTop` 的北面用 `vent` 纹理的上 3 行表现（1 单位高的深缝 + 亮齿），没有真实凹槽。要做真凹槽需把 `FrontTop` 拆成上下两根（+1 cube）并加一块炭黑背板（+1 cube）= 18 cube。
3. **主体东西内缩 0.15**：为了让加强筋凸出，正面的左右两个角上有 0.15 宽的竖缝（正面框条与侧壳之间的台阶）。近距离可见，属设计取舍。
4. **贴面偏移**：面板面 0.86 与主体前表面 1.0 相距 0.14；灯背 0.875 与面板面 0.86 重叠 0.015（刻意嵌入，避免缝隙透光）；筋内表面 15.88 与主体面 15.85 相距 0.03。全部没有共面，理论上不会 z-fighting，但**未在游戏里验证**。
5. **UV 全部按面展开**（`autouv` 关闭、手写 UV，均为 0..16 / 或 panel 的 0..10、0..8），没有 rotation，没有 mixel；`FrontTop` 的北面 UV 是 `[0,0,16,3]`。
6. **顶/底为纯瓷白**：概念图里顶面是「钢框 + navy 凹槽」，按 lead「顶/底保持简单」的要求没有做；若后续要统一工业风可再加。
7. **未导出、未进游戏**：没有 Java block model JSON、没有 blockstate、没有纹理命名空间路径；本轮只到 bbmodel + 截图。

## 备注

- 模型名 `machine_frame`，组名 `01 Shell` / `02 Panel` / `03 Status` / `04 Ribs`，与后续机器保持一致的分组前缀，便于批量导出和替换。
- 状态灯当前是静态纹理（上亮下灭），只作外观示意；实际运行时如果需要 2×2 动态状态，建议在 BER 里用四块小面板的 `BlockEntity` 状态切换纹理，或直接复用进气塔的 `display_empty_*` 思路。
